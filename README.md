# ToxicLens — Toxic Comment Detection Platform

A production-style full-stack implementation around the supplied Keras toxic-comment model.

## Architecture

```text
React + Vite
    │
    │ REST/JWT
    ▼
Node.js + Express ─────── MongoDB
    │                         ▲
    │ internal REST           │ users / predictions / audit
    ▼                         │
Python FastAPI + Keras ──────┘
    │
    ├── toxic_comment_model.h5
    └── tokenizer.pkl
```

### Model contract recovered from the supplied notebook/files

- Input: cleaned comment text
- Vocabulary: 60,000 words
- Sequence length: 200
- Padding/truncation: post
- Output: 6 sigmoid probabilities
- Labels: `toxic`, `severe_toxic`, `obscene`, `threat`, `insult`, `identity_hate`
- Training loss: binary cross entropy
- Architecture: Embedding → 2× Bidirectional LSTM → average/max pooling → Dense 128 → Dense 64 → six-label sigmoid output.

The notebook explicitly uses the same `clean_text`, tokenizer and `pad_sequences` path for inference, so the ML service mirrors that preprocessing exactly.

## Roles

### Public User

- Register/login
- Analyze one comment
- Choose classification threshold
- See label probabilities and risk summary
- Save/view own prediction history

### Researcher

- Everything a user can do
- Batch prediction through CSV upload
- Research dashboard and aggregate prediction statistics
- Download batch results
- View model information

### Admin

- User management
- Promote/demote researchers
- Activate/deactivate accounts
- Platform/model health dashboard
- Audit log access

## Requirements

- Node.js 20+
- Python 3.10–3.13
- MongoDB 7+ (local or Atlas). MongoDB Compass is the GUI; the app connects to MongoDB itself.
- Python environment capable of running TensorFlow/Keras with the supplied H5 model.

## Run locally

### 1. MongoDB

Start MongoDB locally, then use Compass to inspect `toxic_guard`.

Default URI:
`mongodb://127.0.0.1:27017/toxic_guard`

### 2. ML service

```bash
cd ml-service
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Copy the supplied files from `model/` into the project `model/` directory (already included in this package).

### 3. Node API

```bash
cd backend
npm install
copy .env.example .env   # Windows
# cp .env.example .env   # macOS/Linux
npm run seed:admin
npm run dev
```

### 4. React

```bash
cd frontend
npm install
npm run dev
```

Open the Vite URL shown in the terminal, normally `http://localhost:5173`.

## Default admin

Set these before running the seed command:

```env
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=ChangeMe_123!
```

The seed command creates the admin only if that email does not exist.

## Important model compatibility note

The supplied metadata identifies Keras 3.13.2 and the H5 model is loaded by the Python service, not by Node or the browser. `requirements.txt` uses Keras 3.12.4 on Python 3.10, where Keras 3.13.2 is not available, and Keras 3.13.2 on Python 3.11+. This avoids trying to reproduce Python/Keras inference in JavaScript and keeps the exact tokenizer/model preprocessing together.

If your local TensorFlow/Keras combination cannot open the H5 file, use the `.keras` artifact generated by the notebook instead, or install a compatible Keras 3 + TensorFlow environment. Do not change tokenization rules unless you intentionally retrain the model.
